RETAIL OLTP SCHEMA — MERCHANDISING SCORECARD & ANALYTICS

Version: 1.0
Purpose: OLTP schema design with descriptions and DDLs for Retail Merchandising Sales, Profit, Markdown, Season Performance, Location Analysis, and Forecast metrics.

=================================================================
1. OVERVIEW
=================================================================

This OLTP schema supports retail merchandising operations required for the following dashboard and analytical areas:

1. Merchandising Scorecard — Merchandise Sales and Profit dashboard
   - Current Top 10 Sale Items
   - Current Sales & Profit Contribution

2. Merchandising Scorecard — Markdowns dashboard
   - Current Markdown Scorecard
   - Markdown to Sales Ratio

3. Merchandising Scorecard — Merchandise Performance dashboard
   - Season Performance

4. Merchandising Analysis — Merchandising Location Analysis dashboard
   - Daily Sales & Profit
   - Current Sales Projection

5. Retail metrics coverage
   - Sales & Profit metrics
   - Cost / Profit metrics
   - Markdown / Markup metrics
   - Sales Forecast metrics

=================================================================
2. RECOMMENDED OLTP SUBJECT AREAS
=================================================================

A. MASTER DATA

1. Product / Item Master — item, item_supplier, supplier
2. Merchandise Hierarchy — merch_division, merch_group, department, merch_class, merch_subclass
3. Organization / Location Hierarchy — org_chain, region, district, store
4. Season — season, item_season
5. Price Book — item_price
6. Cost Book — item_cost
7. Calendar — business_calendar

B. TRANSACTION DATA

1. Sales Transaction — sales_transaction_header, sales_transaction_line
2. Markdown Event — markdown_event
3. Markup Event — markup_event
4. Inventory Snapshot — inventory_snapshot
5. Sales Forecast — sales_forecast
6. Optional Daily Summary — daily_item_store_sales_summary

4.1 MERCHANDISE HIERARCHY
-----------------------------------------------------------------

Purpose:
The merchandise hierarchy supports rollups from item/SKU to subclass, class, department, group, and division.

Tables: merch_division, merch_group, department, merch_class, merch_subclass

DDL:

CREATE TABLE merch_division (
    division_id        BIGINT PRIMARY KEY,
    division_code      VARCHAR(30) NOT NULL UNIQUE,
    division_name      VARCHAR(100) NOT NULL,
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP
);

CREATE TABLE merch_group (
    group_id           BIGINT PRIMARY KEY,
    division_id        BIGINT NOT NULL,
    group_code         VARCHAR(30) NOT NULL UNIQUE,
    group_name         VARCHAR(100) NOT NULL,
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP,
    CONSTRAINT fk_group_division FOREIGN KEY (division_id) REFERENCES merch_division(division_id)
);

CREATE TABLE department (
    department_id      BIGINT PRIMARY KEY,
    group_id           BIGINT NOT NULL,
    department_code    VARCHAR(30) NOT NULL UNIQUE,
    department_name    VARCHAR(100) NOT NULL,
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP,
    CONSTRAINT fk_department_group FOREIGN KEY (group_id) REFERENCES merch_group(group_id)
);

CREATE TABLE merch_class (
    class_id           BIGINT PRIMARY KEY,
    department_id      BIGINT NOT NULL,
    class_code         VARCHAR(30) NOT NULL,
    class_name         VARCHAR(100) NOT NULL,
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP,
    CONSTRAINT uq_class UNIQUE (department_id, class_code),
    CONSTRAINT fk_class_department FOREIGN KEY (department_id) REFERENCES department(department_id)
);

CREATE TABLE merch_subclass (
    subclass_id        BIGINT PRIMARY KEY,
    class_id           BIGINT NOT NULL,
    subclass_code      VARCHAR(30) NOT NULL,
    subclass_name      VARCHAR(100) NOT NULL,
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP,
    CONSTRAINT uq_subclass UNIQUE (class_id, subclass_code),
    CONSTRAINT fk_subclass_class FOREIGN KEY (class_id) REFERENCES merch_class(class_id)
);

4.2 ITEM / PRODUCT MASTER
-----------------------------------------------------------------

Purpose:
The item master stores sellable SKU/item information. Connects item-level sales, markdowns, markups, pricing, cost, supplier, and season data to the merchandise hierarchy.

Tables: item, supplier, item_supplier

DDL:

CREATE TABLE item (
    item_id            BIGINT PRIMARY KEY,
    item_number        VARCHAR(50) NOT NULL UNIQUE,
    item_description   VARCHAR(255) NOT NULL,
    subclass_id        BIGINT NOT NULL,
    brand_name         VARCHAR(100),
    item_type          VARCHAR(50),
    size_desc          VARCHAR(50),
    color_desc         VARCHAR(50),
    style_code         VARCHAR(50),
    uom_code           VARCHAR(20) DEFAULT 'EA',
    launch_date        DATE,
    discontinue_date   DATE,
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP,
    CONSTRAINT fk_item_subclass FOREIGN KEY (subclass_id) REFERENCES merch_subclass(subclass_id)
);

CREATE TABLE supplier (
    supplier_id        BIGINT PRIMARY KEY,
    supplier_code      VARCHAR(30) NOT NULL UNIQUE,
    supplier_name      VARCHAR(150) NOT NULL,
    supplier_type      VARCHAR(50),
    active_flag        CHAR(1) DEFAULT 'Y',
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP
);

CREATE TABLE item_supplier (
    item_supplier_id   BIGINT PRIMARY KEY,
    item_id            BIGINT NOT NULL,
    supplier_id        BIGINT NOT NULL,
    primary_supplier_flag CHAR(1) DEFAULT 'N',
    supplier_item_code VARCHAR(50),
    effective_from     DATE NOT NULL,
    effective_to       DATE,
    created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at         TIMESTAMP,
    CONSTRAINT uq_item_supplier UNIQUE (item_id, supplier_id, effective_from),
    CONSTRAINT fk_item_supplier_item FOREIGN KEY (item_id) REFERENCES item(item_id),
    CONSTRAINT fk_item_supplier_supplier FOREIGN KEY (supplier_id) REFERENCES supplier(supplier_id)
);

=================================================================
6. KEY METRIC FORMULAS
=================================================================

Net Sales Amount: net_sales_amt = gross_sales_amt - discount_amt - markdown_amt
Total Cost Amount: total_cost_amt = quantity_sold * unit_cost
Gross Profit Amount: gross_profit_amt = net_sales_amt - total_cost_amt
Net Profit Amount: net_profit_amt = net_sales_amt - total_cost_amt - allocated_expense_amt
Markdown to Sales Ratio: markdown_to_sales_ratio = markdown_amt / NULLIF(net_sales_amt, 0)
Sales Contribution %: sales_contribution_pct = item_or_division_net_sales_amt / NULLIF(total_net_sales_amt, 0)
Profit Contribution %: profit_contribution_pct = item_or_division_net_profit_amt / NULLIF(total_net_profit_amt, 0)
Markup %: markup_pct = markup_amt / NULLIF(old_price, 0)
Forecast Variance %: forecast_variance_pct = (actual_sales_amt - forecast_sales_amt) / NULLIF(forecast_sales_amt, 0)

=================================================================
9. RECOMMENDED DATA MODEL GRAIN
=================================================================

item — Grain: One row per sellable SKU/item.
store — Grain: One row per physical or logical selling location.
sales_transaction_header — Grain: One row per POS/order transaction.
sales_transaction_line — Grain: One row per item line in a transaction.
markdown_event — Grain: One row per markdown event per item/location/effective period.
markup_event — Grain: One row per markup event per item/location/effective period.
